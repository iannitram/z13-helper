## Device evidence

Platform: GZ302EA, SteamOS 3.9.5, kernel 7.2, z13ctl 1.4.2, AC power.

| Check | Observation |
|---|---|
| Armoury range discovery | PL1 28–80 W, PL2 32–92 W, PL3 45–93 W; range metadata/permissions only, no live PPT reads |
| Installed desktop Max Fans handler | Two ON → OFF → ON cycles: roughly 8700–8800 RPM on, 5600–6000 RPM off within 15 s, stable for 60 s; on restored full speed |
| CLI profile apply with resident desktop, before race fix | Balanced could remain at 8700–8800 RPM; logs showed Max Fans reapplication and duplicate writes |
| Same resident-app flow after race fix | Two Turbo → Balanced → Turbo cycles: Balanced settled at 3800–4200 RPM without conflicting recovery; Turbo returned to 8700–8800 RPM |
| Power state after fan-only Turbo apply | Backend default `custom.tdp` cleared; explicit configured Turbo limits 70/86/86 W, not a workload power measurement |
| State restored after checks | Turbo, Max Fans on, charge limit 80%, keyboard/lightbar high; services and one desktop instance active |

Fan ramp time varies and can exceed 15 seconds. Curves marked enabled and successful write return
codes are configured/cached status; they do not alone prove physical response. The built-in
20 °C plateau preserves mathematical curve values at/above 40 °C, not proven firmware behaviour
at every temperature or load. Reset-plus-immediate-curve experiments were inconsistent and were
not shipped as a workaround.

## Remaining work

**Post-install finding (#100):** The 0.5.1 installer reported 58 green checks but copied plugin
files while Decky's watcher was active. Steam's CEF log recorded repeated dynamic-import fetch
failures during those copies at 08:05. The frontend subsequently loaded 0.5.1 successfully;
the entry URL returned HTTP 200 with JavaScript content and the registered plugin exposed its
normal `Content` component, title view and dismount handler. The health report had verified
backend startup, not the frontend. The follow-up installer fix stops the loader before replacement;
this finding does not invalidate the earlier fan/power checks.

Issue #86 retains the firmware/kernel causality question and broader cold-boot, suspend/resume,
interactive Game Mode, sustained-load and soak checks. Physical noise/rotation was not independently
measured. #30's long-session memory check remains open. App profiles are not yet mirrored to
z13ctl named profiles and there is no universal cross-process transaction lock (#23).
Post-update repair acceptance (#27) and the other approved 1.0 Musts remain separate work.
